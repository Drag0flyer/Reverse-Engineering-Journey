## 1. Binary Specifications & Environmental Audit
An initial defensive assessment of the target configuration was conducted to analyze active binary protections.

### Mitigation Check:
* **Architecture:** ELF 64-bit LSB executable (x86_64).
* **NX (No-Execute):** `NX enabled`. The Heap and Stack segments are non-executable, preventing raw shellcode delivery.
* **ASLR (Address Space Layout Randomization):** `ON`. Segment base addresses are randomized dynamically at runtime.
* **SSP (Stack Canary):** `Disabled` (Non-factor here as our vector targets dynamic memory allocation structures on the Heap).

---

## 2. Static Analysis & Vulnerability Identification
The operational flow of the application was evaluated using the provided C source code:

```c
int main()
{
  char  *arg = malloc(0x20);
  char  *cmd = malloc(0x400);
  setreuid(geteuid(), geteuid());

  strcpy(cmd, "/bin/ls -l ");
  printf("Enter directory you want to display : ");

  gets(arg);
  checkArg(arg);

  strcat(cmd, arg);
  system(cmd);

  return 0;
}
```

### Vulnerability Mechanics:
1. **Sequential Heap Allocation:** The binary allocates `arg` (`0x20` bytes) immediately before allocating `cmd` (`0x400` bytes). On standard `glibc` implementations, these two memory chunks sit adjacently in the Heap space.
2. **The Dangerous Legacy Function:** The application collects input via `gets(arg)`. Because `gets()` lacks any boundary validation checks, it allows an operator to write an arbitrary amount of data into the bounded `0x20` storage block.
3. **Application Control Hijack:** By overfilling `arg`, the user input breaks past its chunk boundaries, overrunning the intermediate chunk metadata headers and directly corrupting the content of the `cmd` string buffer located downstream.

### Character Filter Bypass:
The application implements a sanitization routine via `checkArg()`, killing the execution path if characters like `;`, `&`, `|`, or `$` are detected. However, this filter only inspects `arg` for command injection structures. It does not mitigate a physical memory overwrite of `cmd`, nor does it filter the comment token character (`#`), making the defense ineffective against a straight buffer rewrite.

## 3. Offset Mapping & Heap Cartography
To find the precise distance between the start of the `arg` pointer and the target `cmd` buffer, a structured pattern sequence was injected:

```text
AAAABBBBCCCCDDDDEEEEFFFFGGGGHHHHIIIIJJJJKKKKLLLLMMMMNNNN
```

The execution environment responded with the following system error:

```text
sh: 1: MMMMNNNN... : not found
```

The string sequence `MMMM` sat directly at the absolute beginning of the corrupted command line executed by `system()`. Counting the preceding characters (`A` through `L`), the mechanical offset required to reach and overwrite the entry threshold of `cmd` was determined to be exactly **48 bytes**.

---

## 4. Exploit Payload Design
While a typical payload might try to overwrite the execution flow with an explicit instruction address, a **Heap Application Data Corruption** approach allows us to rewrite the string argument passed natively to `system()`.

### The Concat & Argument Clashing Challenge:
Due to the subsequent `strcat(cmd, arg)` operation executed by the program, the corrupted buffers merge and loop, appending the original payload to the end of the corrupted string. When attempting to run `/bin/sh`, the shell interprets the remainder of the junk data trailing it as a file target argument, leading to a crash:

```text
/bin/sh: 0: Can't open AAAAAAAA...
```

### The Comment Token Bypass:
To force the command processor to execute our shell and cleanly drop all trailing buffer noise generated by the overflow and concatenation, a Linux shell comment symbol (`#`) was included. By feeding the binary `/bin/sh #`, the trailing junk data is ignored as an inline comment block.

---

## 5. Execution & Shell Interception
Adjusting the padding down to 39 bytes to account for alignment shifting caused by the `strcat` rebuild, the payload was piped natively along with an open descriptor loop (`cat`) to hold interactive terminal persistence:

```bash
(python -c "import sys; sys.stdout.write('/bin/sh #' + 'A' * 39 + '\n')"; cat) | ./ch94
```
